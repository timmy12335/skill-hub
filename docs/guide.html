skill-hub · 參考 Uber 的 agent skill 管理做法

一個 repo 管所有專案的 Claude Code skill

把 skill 集中放在 Skill Hub，每個專案只放一個小設定檔。新專案執行一次 init，之後 hub 更新時執行 sync，不必再為每個專案重新設計管理方式。

需求

Python 3.9 以上，不需安裝套件。eval 需要 claude CLI。

下載

專案檔案庫中的 skill-hub-framework/skill-hub.zip

已驗證

init、sync、lint、hook、stats、真實 eval 都實際跑過。

01為什麼需要

skill 一多，常見的問題是：每個專案各複製一份，改了一處其他專案沒跟上；不知道哪些 skill 真的有人在用；模型升級後，有些 skill 已經沒必要卻還佔著 context。

Uber 用一年把 skill 從 1 個做到 5,000 多個、每月 100 萬次呼叫，靠的是幾個固定的機制。這個框架保留同樣的機制，但縮小到個人或小團隊用一個 Python 檔就能跑：

Uber 的做法本框架的對應
spec.md 編譯出 SKILL.mdspec.md 寫意圖，skillctl compile 用 Claude 產生 SKILL.md 草稿
單一 Git repo 當 marketplaceskill-hub repo，skills/ 下分三層
Domain / Core / Always-on同名三個資料夾，CODEOWNERS 控制審查
aifx CLI＋六層設定skillctl＋四層設定（hub → 使用者 → 專案 → 本機）
find-skillsalways-on skill find-skills，依 eval 分數與用量排序
Eval 5/80/15＋ablationevals/cases.jsonl，skillctl eval --ablation
OpenTelemetry hookshook 寫本機 JSONL，可選擇再送 OTLP
Papercut 自動回報always-on skill skill-papercut，可轉成 eval 案例

03一個 skill 的組成

每個 skill 是一個資料夾。安裝到專案時只複製 agent 需要的檔案，spec.md、evals/、CHANGELOG.md 這些作者端資料留在 hub。

commit-message/
├── spec.md            # 給人看：目標、觸發時機、產出、必用／禁用工具、退場條件
├── SKILL.md           # 給 agent 看：frontmatter＋步驟，500 行內
├── references/        # 需要時才讀的細節
├── scripts/           # 需要時才執行的腳本
├── evals/cases.jsonl  # 測試案例
└── CHANGELOG.md

三段載入

Claude Code 不會一次把整個 skill 塞進 context，所以 description 寫得好不好，決定了 skill 會不會被用到。

永遠載入name＋description約 100 tokens。寫清楚「做什麼」和「什麼時候用」。
觸發時載入SKILL.md 本文500 行以內的步驟。lint 會擋超過的。
用到才載入references/、scripts/大段資料、範例、腳本放這裡。

SKILL.md frontmatter

---
name: commit-message
description: Writes git commit messages in Conventional Commits format from the staged diff. Use when the user asks to commit, write a commit message, or describe staged changes.
metadata:
  version: 1.1.0      # 每次修改都要升，CI 會檢查
  owner: platform     # 誰負責維護
  tier: core
  status: active     # active → deprecated → retired
---

04導入新專案

hub 只需要準備一次。之後每個新專案都是第 3 步這一行。

  1. 把 hub 放進自己的 Git repo

    fork 或複製 timmy12335/skill-hub，把 .github/CODEOWNERS 裡的帳號改成你自己的，並依升級與退場的說明設定分支保護。

  2. 在電腦上 clone 並設 alias

    git clone git@github.com:<你>/skill-hub.git ~/skill-hub
echo 'alias skillctl="python3 ~/skill-hub/tools/skillctl.py"' >> ~/.zshrc

  3. 在專案裡執行 init

    cd ~/projects/my-app
skillctl init --plugins starter

    這一步會：建立 .skillhub.json；把 .skillhub.local.json 加進 .gitignore；在 .claude/settings.json 註冊使用量與自建 skill 偵測 hook 並啟用必裝的 superpowers plugin；安裝 always-on 和 starter 組合包裡的 skill。

    ✓ 建立 .skillhub.json
✓ 已在 .claude/settings.json 註冊使用量 hook
+ 安裝 commit-message v1.1.0  (plugin:starter)
+ 安裝 find-skills v1.0.0  (always-on)
+ 安裝 skill-papercut v1.0.0  (always-on)
+ 啟用 Claude Code plugin superpowers@superpowers-marketplace（必裝）
✓ 3 個 skill 已同步到 .claude/skills

    接著在專案裡開 Claude Code，同意安裝 superpowers plugin。之後可以隨時用 skillctl doctor 檢查狀態。

  4. 把產生的檔案 commit 進專案

    commit .skillhub.json、.claude/skills/、.claude/skills.lock.json、.claude/settings.json、.claude/hooks/。這樣隊友 clone 下來不需要 hub 也能直接用 skill。

  5. hub 有更新時同步

    cd ~/skill-hub && git pull
cd ~/projects/my-app && skillctl sync      # 只會更新內容有變的 skill

05分層設定

四層 JSON 依序合併，後面的層級覆蓋前面。清單欄位會累加，exclude 最後套用，所以任何一層都能排除不要的 skill。

層級檔案適合放什麼
1 hubskill-hub/skillhub.json全部專案的預設，通常不動
2 使用者~/.config/skillhub/config.json你在每個專案都想要的個人 skill
3 專案.skillhub.json（進版控）這個專案需要的組合包和 skill
4 本機.skillhub.local.json（不進版控）只在自己電腦試用、或暫時關掉某個 skill
欄位合併方式說明
plugins累加plugins/<名稱>.json 的組合包
include累加單獨加裝的 skill
exclude累加，最後套用不要裝的 skill，連 always-on 也能排除
always_on覆蓋設 false 就不裝 always-on 層
mode覆蓋copy（預設，可 commit）或 link（symlink，改 hub 立即生效）
pin合併{"commit-message": "1.0.0"} 固定版本
 
// my-app/.skillhub.json
{
  "hub": "/Users/you/skill-hub",
  "plugins": ["starter"],
  "include": ["api-review"],
  "exclude": []
}

// my-app/.skillhub.local.json：只在我這台電腦關掉 papercut
{ "exclude": ["skill-papercut"] }

必裝的 Claude Code plugin

hub 的 skillhub.json 用 agent_plugins 宣告每個專案都要有的 plugin，目前必裝的是 superpowers。sync 會把它寫進專案的 .claude/settings.json，第一次在專案開 Claude Code 時同意安裝即可；隊友 clone 後也會被提示安裝。plugin 本身由 Claude Code 安裝與更新，不會複製進專案。

// skill-hub/skillhub.json（節錄）
"agent_plugins": [{
  "id": "superpowers@superpowers-marketplace",
  "required": true,
  "marketplace": {"name": "superpowers-marketplace", "repo": "obra/superpowers-marketplace"},
  "provides": ["brainstorming", "writing-plans", "systematic-debugging", "…"]
}]
欄位說明
required只有 hub 能設。專案或本機用 exclude_agent_plugins 也排除不掉
marketplace寫進 extraKnownMarketplaces，讓 Claude Code 知道去哪裡裝
providesplugin 內建的 skill 名稱。hub 裡的 skill 不能同名，lint 會擋，避免兩份指令互相衝突

專案需要其他 plugin 時，在 .skillhub.json 的 agent_plugins 加上 id 即可，例如 ["playwright@claude-plugins-official"]。

06寫新 skill

每個 skill 都走同一條生命週期：

撰寫→測試→上架→依使用資料改進→模型變強後退場

  1. 從範本建立

    skillctl new api-review --tier domain --owner egbert

    一律先放 domain。用量穩定後用 skillctl promote 升到 core，只有幾乎每次對話都用得到的才升到 always-on（見升級與退場）。

  2. 填 spec.md，再產生 SKILL.md

    spec 寫目標、使用者會怎麼說、不該觸發的情境、產出、必用與禁用工具、成功標準。superpowers 的 brainstorming 適合用來釐清 spec，writing-skills 適合用來寫 SKILL.md。然後：

    skillctl compile api-review --run   # 產生 SKILL.md.draft，比對後再覆蓋

  3. 寫 eval 案例並檢查

    skillctl lint api-review
skillctl eval api-review

    lint 會擋：名稱和資料夾不一致、description 空白或還是範本文字、本文超過 500 行、沒有 owner 或版號、連到不存在的 references 檔案。

  4. 開 PR

    CI 會跑 lint、檢查 eval 格式，並確認修改過的 skill 有升版號。在 repo 設定 SKILL_EVAL_ENABLED=true 和 ANTHROPIC_API_KEY 後，core 與 always-on 的變更會自動跑真正的 eval。

07專案自建 skill 自動送審

在任何專案的 .claude/skills/ 裡自己新增 skill 時，不需要手動搬到 hub。Claude Code 結束時，hook 會發現這個新 skill，自動開 PR 送進 hub 審核，通過後由 hub 接手管理。

  1. 偵測

    init 會註冊 SessionEnd hook。它比對 .claude/skills/ 和 lock 檔，找出 hub 還沒有的 skill，在背景執行 skillctl adopt，不會拖慢 Claude Code 結束。結果寫在 ~/.skillhub/adopt.log。

  2. 送審

    adopt 會補齊 frontmatter（版號 0.1.0、owner、tier: domain），在暫存 worktree 從 hub 的 origin/main 開 adopt/<name> 分支，加上 spec.md 和 CHANGELOG 草稿後推上去開 PR。你目前的 hub checkout 不受影響。

    [2026-11-24T15:19:00] my-app: 發現新 skill sql-style（pr）
✓ sql-style 已送審：https://github.com/timmy12335/skill-hub/pull/9

  3. 審核

    hub 的 CI 跑 lint。PR 只動到 skills/domain/ 時，lint 通過就自動合併；只要碰到 core、always-on 或工具程式，就一定要人審。PR 描述會列出待補的 spec 和 eval。

  4. 接手

    審核期間專案繼續用自己的版本，sync 不會覆蓋。合併後在 hub git pull，專案再 skillctl sync，就會顯示「已收編進 hub，改由 hub 管理」。之後其他專案也能用 skillctl install sql-style 安裝。

auto_adopt行為
"pr"（預設）自動開 PR 送審
"notify"只記錄在 adopt.log，等你手動執行 skillctl adopt
"off"不偵測
需要：本機裝好 GitHub CLI 並執行過 gh auth login。自動合併靠 hub repo 的 GitHub Actions，不需要開啟 repo 的 auto-merge 設定。

名稱和 hub 既有 skill 或 superpowers 的 skill 重複時，adopt 會拒絕並提示改名。已收編過的 skill 若在專案內又改了，用 skillctl adopt <name> --again 送更新。

08升級與退場

skill 放在哪個資料夾就是哪一級。新 skill 一律從 domain 開始，證明自己有用之後再往上升。升級和降級都用指令完成，指令會搬資料夾、改 tier、升版號、寫 CHANGELOG，你只要 commit 並開 PR。

$ skillctl promote api-review --dry-run
api-review：domain → core
  ✓ lint 無錯誤
  ✓ 狀態為 active（目前 active）
  ✓ 有負責人（egbert）
  ✓ eval 案例 ≥ 5（目前 5）
  ✗ 目前版本的 eval 通過率 ≥ 70%（沒跑過 eval）
  ✓ description ≤ 1024 字元（目前 127）
  ✗ 30 天內被 ≥ 2 個專案使用（目前 0）
  ✗ 30 天內使用 ≥ 10 次（目前 0）

3 項未通過，沒有變更。

升級條件

升級預設條件
domain → corelint 無錯誤、狀態 active、有負責人、至少 5 個 eval 案例、目前版本的 eval 通過率 ≥ 70%、30 天內被 2 個以上專案共使用 10 次以上
core → always-on上面全部，再加上至少 8 個案例、跑過 --ablation 且有 skill 比沒有好、description 300 字元內、3 個以上專案共使用 30 次以上

門檻可以在 hub 的 skillhub.json 調整，例如 "promotion": {"core": {"min_uses": 5}}。條件沒全過但你確定要升，可加 --force，未通過的項目會寫進 CHANGELOG，方便審查時看到。

使用量來自你自己電腦上的紀錄檔。多人團隊若要合併大家的使用量，請把 hook 的資料送到共用的 OpenTelemetry collector。

降級與退場

skillctl demote api-review --status deprecated --reason "ablation 無差異"
skillctl demote api-review --status retired    # 各專案下次 sync 時移除
skillctl demote api-review --to domain         # 降一層

讓 GitHub 審查跟著分級

CODEOWNERS 已經設定好，還需要在 repo 的 Settings → Branches（或 Rules → Rulesets）替 main 開啟三個選項：

設定效果
Require a pull request，approvals 設 1所有改動都要經過 PR 和 1 人 review
Require review from Code Ownerscore/、always-on/、tools/ 一定要負責人審過
Require status checks：lintCI 沒過不能合併
只有你一個人時：GitHub 不允許核准自己的 PR，前兩項會讓你無法合併。這時先只開第三項，等有協作者再開前兩項。

09Eval 與 ablation

skillctl eval 會為每個案例建一個乾淨的暫存專案，只裝這個 skill 和 always-on 層，用 claude -p 執行，再檢查 skill 有沒有被觸發、輸出是否符合條件。預設只給 agent 唯讀工具，需要更多用 --allow-tools。

案例格式

{"type": "golden", "prompt": "我 stage 好了，幫我寫 commit message",
 "setup": "git init -q && echo 'x' > a.py && git add a.py",   // 選填：先建立情境
 "expect": {
   "triggers": true,              // 該觸發（false＝不該觸發）
   "regex": ["(feat|fix|chore)(\\(.+\\))?: "],
   "contains": [], "not_contains": [],
   "tool_order": ["Bash", "Edit"]  // 工具呼叫順序
 }}

案例比例

5
real 80%
15%
golden：一定要對的經典案例real：真實請求，含「不該觸發」的self：作者想到的邊界

real 案例的來源是日常使用和 papercut 回報。案例少於 10 個時不檢查比例。

通過率怎麼看

目標落在 70–90%。低於 70% 先修再上架；100% 通常代表案例太簡單，改 skill 時測不出差異，工具會提醒你加困難案例。

Ablation：這個 skill 還有價值嗎

加 --ablation 會對每個案例再跑一次「沒有這個 skill」的對照組。以下是框架附的 commit-message 實際跑出的結果：

100%
有 skill：5 個案例全過
80%
沒有 skill：golden 案例沒有寫出 Conventional Commits 格式

差距 +20%，代表 skill 仍有作用。如果某天對照組追平，就執行 skillctl demote <name> --status deprecated，下一輪再改成 retired，sync 會自動從各專案移除。同時這次 100% 也觸發了「案例太簡單」的提醒，下一步該補幾個困難案例。

10使用量與回報

Hook 記錄什麼

init 註冊兩個 hook：agent 呼叫 Skill 工具時（PostToolUse），以及你手動輸入 /skill-name 時（UserPromptSubmit，只取指令名稱）。每筆寫一行到 ~/.skillhub/usage.jsonl：

{"ts": "2026-11-24T14:16:23+00:00", "skill": "commit-message", "version": "1.1.0",
 "source": "agent", "session": "ba7816bf8f", "project": "c863215129", "error": null}

不記錄 prompt 或檔案內容，session 和專案路徑都只存雜湊值。設定 SKILLHUB_OTLP_ENDPOINT 會另外送一份到 OpenTelemetry collector。hook 出錯時一律靜默，不會擋住 agent。

看統計

以下數字為示意。

$ skillctl stats --days 30
skill                 次數  session  專案  錯誤  最後使用    版本
commit-message          42       18     3     0  2026-11-24  1.1.0
find-skills              7        6     2     0  2026-11-20  1.0.0

30 天內沒被用過（退場候選，或 description 寫得讓 agent 找不到）：
  - domain/api-review

沒人用的 skill 有兩種可能：真的不需要，或 description 沒寫到使用者會說的關鍵字。先改 description 再觀察一輪。

Papercut：把小問題變成測試

always-on 的 skill-papercut 會在使用者糾正了某個 skill 的產出時，讓 agent 自己回報一筆。你也可以手動回報：

skillctl papercut commit-message "不該加 emoji 前綴" --prompt "幫我 commit"
skillctl papercut commit-message --to-eval   # 全部轉成 real 類型的 eval 案例

12常見問題

copy 和 link 模式要選哪個？

團隊專案用 copy：skill 跟著專案進版控，隊友不需要 hub。自己同時開發 hub 和專案時，在 .skillhub.local.json 設 "mode": "link"，改 hub 立刻生效。

專案裡直接改了 .claude/skills/ 的檔案會怎樣？

由 hub 安裝的 skill，下次 sync 時 hub 版本有變就會被覆蓋，要改請回 hub 改並升版號。自己新增、hub 還沒有的 skill 不會被覆蓋，會自動送審（見自建 skill 送審）。

沒有 GitHub、只有自己用可以嗎？

可以。hub 只是一個資料夾，CI 和 CODEOWNERS 是選用的。建議至少保留 skillctl lint 當 git pre-commit hook。

eval 要花多少？

每個案例是一次 claude -p 呼叫，最多 8 回合；加 --ablation 會變兩倍。平常只對有改動的 skill 跑，--dry-run 只檢查格式、不呼叫模型。

為什麼 superpowers 不直接複製進 hub？

它是獨立維護、更新頻繁的 plugin。交給 Claude Code 的 plugin 機制安裝，就能跟著上游更新；hub 只負責規定「一定要裝」，並確保自己的 skill 不和它撞名。

手動輸入 /skill-name 會被記錄嗎？

會，hook 只取開頭的指令名稱，而且必須是專案裡已安裝的 skill 才記錄，後面的文字不會寫入。
